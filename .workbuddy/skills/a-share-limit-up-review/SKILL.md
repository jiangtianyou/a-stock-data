# A股涨停复盘（今日 vs 昨日 + 资金运动）

盘后复盘：把当日涨停结构拆成「情绪温度 → 资金去哪 → 质量如何 → 明日观察」，用**今日与前一交易日同口径对比**得出结论。

## 交付物

`reports/涨停复盘对比-{D0}.html` —— 浅底深字、结论先行、ECharts 5、**红涨绿跌**。
报告必须能独立读懂：首屏给结论，图表给证据，末尾给数据可信度说明与风险提示。

## 执行流程（四步，全程零三方依赖）

从**项目根目录**执行（脚本按 CWD 定位 `out/`、`reports/`；也可用 `ZT_ROOT` 覆盖）。

## 分析维度（八项，缺一不可）

| # | 维度 | 看什么 | 怎么解读 |
|---|---|---|---|
| 1 | **情绪温度计** | 涨停/炸板/封板率/跌停/涨停跌停比，做**三日序列** | 封板率与跌停数同时反向 = 退潮/修复的拐点 |
| 2 | **指数与量能** | 分指数涨跌幅 + 成交额环比 | 增量资金去了哪个市值/风格（对比科创50 与上证50 的量能增速） |
| 3 | **连板梯队** | 1..N 板分布两日对比 + 最高板 + 连板股名单 | 首板占比过高 = 宽度靠补涨、高度未打开 |
| 4 | **主线归因** | `reason_type` 关键词聚类 | 一只票可命中多条线，**须注明家数之和大于总数** |
| 5 | **行业迁移** | 东财 `hybk` 今日 vs 昨日 | 显式标流入/流出，是判断"资金搬家"的直接证据 |
| 6 | **昨涨停股今日表现** | 晋级率 + 均涨/**中位**/翻绿比例 + 最强最弱，**按首板/连板分组** | 均值被极端值拉动时以中位数为准 |
| 7 | **封板时间分布** | 竞价/开盘半小时/上午/午后/尾盘，两日对比 | 早盘一致 + 高炸板率 = 盘中瓦解；时间后移 = 逐波承接 |
| 8 | **成交结构** | 涨停股合计成交额及占两市比重、封单合计与中位数、一字板 vs 换手板 | 薄封单 + 高换手 = 抛压已消化但承接不牢 |

## 口径铁律（三条，违反必然得出荒谬结论）

1. **同花顺 `currency_value` 不是成交额**（实测差 10 倍）。成交额、换手率、市值、封单**一律取东财**；同花顺只用于 `reason_type`、`high_days`、`limit_up_type`、时间戳与 `limit_up_count`/`limit_down_count` 汇总数。
2. **跌停/炸板家数用 `limit_up_count`/`limit_down_count` 汇总字段**，不要数池子返回的条数（实测 9/16 跌停 4 家，跌停池返回 0 条）。
3. **排序必须带完整 tie-break**。仅按计数排序时，同分项先后取决于 `set()` 迭代顺序，而 str 哈希每进程随机化 → 同一份数据两次跑出的 Top18 行业不一样（已踩坑并修复）。

更多接口细节与坑见 `references/data-sources.md`、`references/pitfalls.md`。

## 必做自检

- [ ] `涨停股合计成交额 ÷ 两市成交额` **通常**落在 3%~8%（口径自检）。该比值与涨停家数强相关，
      家数腰斩时会自然跌破下限（09-17 仅 47 家 → 2.0%，前一交易日 89 家 → 4.3%）；
      此时用「单只中位成交额」二次校验（09-17 中位 5.53 亿 > 前日 3.88 亿 → 字段源无误），并在报告口径说明里写明。
- [ ] 封板时间双源一致性 **≥95%**（东财 `fbt` vs 同花顺时间戳），低于说明字段错位
- [ ] 报告内所有 `HH:MM` 合法：炸板池时间由东财 `fbt`（HHMMSS 整数）格式化，**必须 `zfill(6)` 后再切**，
      否则 10:00 前会渲染成 `92:50` 这种非法值。出图后 `grep -o "[0-9][0-9]:[0-9][0-9]"` 自查，不允许出现 `9x:xx`
- [ ] 报告无占位符残留：脚本已自动打印 `placeholder residue:`，必须为空列表
- [ ] **北交所差额自检**：东财 `em_ZT.tc` 与同花顺 `num` 的差额须能**全部解释为 `920xxx` 北交所标的**
      （09-18 差 1 只 920298；09-21 差 2 只 920478/920427）。若差额里出现沪深代码 → 字段错位，必须排查；
      差额解释得通时，在「数据口径」里写明「已按沪深口径取 N 家」并列出北交所代码，不要静默取其一。
- [ ] 同花顺跌停池明细接口 `dataapi/limit_up/limit_down_pool` **会 404**（09-21 实测，`ths_dt` 为 None）：
      此时跌停家数只能用汇总字段 `limit_down_count`，报告须声明「明细池不可用、未列名单」，不要写成 0 家。
- [ ] **跌停家数两源不一致时先看 `em_DT.pool` 是否为空**：09-23 实测同花顺汇总 12 家、东财 `em_DT.tc`=13、
      而 `em_DT.pool` 为空 → **差额 1 只无法归因**。此时一律取同花顺汇总口径，并在「数据口径」里写明两源数值、
      差额与不可归因的原因；**不要**因为 pool 为空就写「东财 0 家」（`tc` 与 `pool` 是独立字段，会自相矛盾）。
      另：跌停封死率取 `limit_down_count.today.rate`，与封板率一样是判断退潮形态的关键（09-23 跌停 12 家、封死率 75%）。
- [ ] **取涨停名单代码用 `ths_zt["info"]`，不是 `ths_zt["total"]["info"]`**：`ths_zt` 是分层字典
      （`total`/`limit_down_count`/`date`/`trade_status`/`info` 平级）。写错层级会**静默得到空集**，
      使下面的北交所差额自检把全部涨停股当成"差额"而误报字段错位。见 `references/pitfalls.md` 第 14 条。
- [ ] **「收在涨停价但两源涨停池都不收录」的票要单列披露、不改家数**：09-22 瑞芯微（+10.00%）、
      09-24 三羊马（+10.01%）收盘价等于涨停价，却只出现在东财炸板池（推测按「收盘是否有封单」筛选）。
      家数一律取两源汇总口径，报告「数据口径」里单列一条写明代码/涨幅/所在池；这类票计入「回封」。
      见 `references/pitfalls.md` 第 16 条。
- [ ] **行业家数持平时必须比对成分集合**：09-24「通用设备」6→6 家，但成分只留存 1 只（轮换率 83%），
      昨日是「电子测量/科学仪器」、今日是「仪器 + 机器人零部件 + 军工物流」三叙事故装。
      **禁止**只凭家数持平就下「该行业延续」的结论；主线归因改用 `reason_type` 关键词聚类 + 碰撞项复核。
      见 `references/pitfalls.md` 第 17 条。
- [ ] **判读「缩量下跌 + 封板率回升」必须同时算参与度与承接力**：
      参与度 = 触及涨停家数（`num + open_num`）、承接力 = 封板率（`num / history_num`）、破坏力 = 跌停 `num` 与封死率。
      09-24 参与度 77→61 而承接力 66.2%→83.6% → 是「参与收缩 + 失败率下降」（**收缩式锁仓**），**不是**资金回流。
      见 `references/pitfalls.md` 第 18 条。
- [ ] **炸板池 `em_ZB` 须区分「回封」与「未回封」**：池内可能含**收盘仍涨停**的票
      （09-22 实测 18 只中瑞芯微 603893 收 +10.00%，即盘中打开后回封）。
      按收盘涨幅是否达涨停（创业板/科创板阈值用 19.8%）拆分，报告里分列两类，
      **不要把回封票当作「大票炸板」的利空证据**。见 `references/pitfalls.md` 第 12 条。
- [ ] **`idx_cmp` 只覆盖 4 个指数**（上证/深成/创业板/科创50）：要展示上证50、中证1000、国证2000
      的「昨日」涨跌幅或**成交额环比**时，须从上一交易日 `out/zt_review_{D1}.json` 的 `indexes` 补全
      （`pct` / `amount_wan`），否则表格渲染成 `—`。分析「增量资金去权重还是小微盘」必须用到它。
      见 `references/pitfalls.md` 第 13 条。
- [ ] **同一交易日重复触发（自动化重跑）先做幂等比对**：重新抓取后按 `code` 排序归一化再比 JSON，
      **只比 `D0` / `D1` / `today_zt_quotes` / `yesterday_zt_today` 四个核心键** —— 一致即判定「数据已稳定」，
      直接复用已有报告（不必产生新提交）；若封单等字段有变 → 重跑 `zt_analyze` + `zt_report_{D0}.py`。
      **比对时必须排除** `generated_at`、`dates`、`indexes`、`index_hist`：后两者存在接口侧抖动
      （`indexes` 的 `float_mv/total_mv` 尾数、`index_hist` 的当日行窗口滑动，见下条），
      纳入比对会产生假差异而误判、白跑一遍完整流程。
- [ ] **指数日线的最后一行不等于「当日」**：`index_hist[code].rows` 在盘后会把当日行移出返回窗口
      （09-21 实测 16:11 含 `20260921`、16:34 起不含）。本流程的当日成交额取自**实时快照** `indexes[sym].amount_wan`，
      历史行按**显式日期**查 D1/D2，故不受影响；但**禁止**用 `rows[-1]` 当当日，否则会静默回退到前一交易日且不报错。
      详见 `references/pitfalls.md` 第 11 条。
      另：同花顺封单 `order_amount` 在**收盘后 30 分钟内仍会刷新**（09-21 实测 4 只差 18~54 倍），
      而报告统一取东财 `fund`，故不受影响——但不要据此认为「收盘即稳定」。详见 `references/pitfalls.md` 第 10 条。
- [ ] `_check_js.py` 输出 `OK`；`_shot.py` 报告的图表容器 `canvas` 数 >0 且无控制台错误

## ECharts 加载（2026-09-20 起）

本 skill 的模板与项目周报都使用**本地托管 + CDN 兜底**：

```html
<script src="../assets/echarts.min.js"></script>
<script>if(typeof echarts==='undefined'){document.write('<script src="https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js"><\/script>');}</script>
```

`assets/echarts.min.js` 已在仓库中（1.0MB）。**不要退回纯 CDN 写法**：jsdelivr 在 Playwright 侧会间歇性
`ERR_CONNECTION_RESET`，表现为自检时所有图表容器 `canvas=0` + `PAGEERROR: echarts is not defined`，
而同一时刻 `curl` 却能下载成功——容易误判成图表配置写错。

## 已知失效

- **通达信 MCP 有调用配额**，耗尽返回 `unauthorized / quota is below 10`；本流程不依赖它。
- 东财 `push2his` / `push2` 批量接口有 IP 级限流（被限后全域名同时 RST）；`push2ex`（涨停池）实测稳定。

## 非交易日 / 数据缺失

- 当日非交易日：`ths_zt.info` 为空且 `limit_up_count` 为 0 → **不要生成逐日报告**。
- **周末 / 长假（无新交易时段）不要只回一句「今日休市」**，改用**周度复盘**兜底（2026-09-20 起）：
  ```bash
  PYTHONIOENCODING=utf-8 $PY scripts/zt_week_analyze.py {上周五} {最近交易日}   # 需先有对应日期的 zt_review_*.json
  PYTHONIOENCODING=utf-8 $PY scripts/zt_week_report.py  {上周五} {最近交易日}
  # → reports/涨停周报-{start}至{end}.html
  ```
  周报脚本自动合并**所有** `out/zt_review_*.json`（按日期建映射，同日多份优先 D0 份），
  缺哪个日期就补跑一次 `zt_fetch.py`。周报的晋级率改用「两日涨停池代码集合取交集」，
  **不依赖行情快照**，因此可跨历史日期批量复算（实测与逐日报告的快照口径一致）。
- 昨日池为空（前一日休市）：`zt_analyze.py` 的「晋级率」段样本为 0 会报除零，需先确认 D1 是交易日。
