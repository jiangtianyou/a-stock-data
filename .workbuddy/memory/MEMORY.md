## 脚本与工程约定

- **两段式**：先抓取落盘 `out/*.json`，再分析/出报告。长时抓取用域名轮换 + 指数退避 + **逐品种增量打印**（不要 `| tail -N`，会缓冲到结束）。网络脚本统一绕过代理（`ProxyHandler({})` / `Session.trust_env=False`）。
- **抓取脚本必须「全部成功才覆盖落盘」**（写 `.tmp` 再 `os.replace`），否则重跑会把好数据覆盖成空。
- **盘后复跑幂等比对只比四个核心键**：`D0`/`D1`/`today_zt_quotes`/`yesterday_zt_today`；排除 `generated_at`、`dates`、`indexes`（市值尾数抖动）、`index_hist`（**盘后把当日行移出返回窗口**）。当日成交额一律取实时快照 `indexes[sym].amount_wan`，**禁止用 `index_hist[code].rows[-1]` 当当日**（会静默回退一天）。
- **排序 tie-break 必须完整**：`sorted(set(...))` 同分项受 str 哈希随机化影响 → 补 `(计数, -今值, -昨值, 名称)`。
- **同一文件的多个 Edit 不要并行提交**（实测 4 个只生效 1 个）；批量改脚本用「一次性补丁 + `assert a in s`」。Git Bash 下 grep/sed 处理 UTF-8 中文常失效 → 用 Read 工具或 python。
- **涨停链的权威脚本只在 skill 内**（`.workbuddy/skills/a-share-limit-up-review/scripts/`）。项目根 `scripts/zt_fetch.py` / `zt_analyze.py` 曾是日期硬编码的过期副本，误用会**静默写错日期且不报错** → 已改写为 `runpy` 转发。**项目根 `scripts/` 只放 `zt_report_{D0}.py` / `zt_week_*.py`。** 自检：抓取首行必须打印 `== 复盘 {D0} 对比 {D1} ==`。
- **依赖归属**：`pandas/numpy` 在 managed venv（`~/.workbuddy/binaries/python/envs/default/Scripts/python.exe`）；**`playwright` 只在系统 python 3.11**，venv 跑 `_shot.py` 会 ModuleNotFoundError。
- **校验 GitHub Pages 在线页：curl 必须加 `--ssl-no-revoke`**（本机 schannel `(35) 0x80092013` = CRL 不可达，表现 `http_code=000`、`-o` 不落盘 → 极易误判"404/未部署"）。超时 ≥120s（首字节可能 50s+）。**内容/标题不符时先重取一次**（CDN 旧边缘节点会返回上一份报告）。
- **`senti[D0]["yest"]` 是「前一交易日」统计（= D1 值），不是当日**：当日/前日「触及涨停、触及跌停、封死率」一律取 `B["dates"][D0]["ths_zt"]["total"]["today"]["history_num"]`；`limit_down_count` 与 `total` 是 `ths_zt` 下**平级键**。自检：`触及涨停 ≥ 涨停家数`。
- **`zt_fetch.resolve_dates` 只取前 2 个参数** → `review` 文件只含 D0/D1；`zt_analyze.py` 三日序列仍正确（`days[0]` 用 `senti[D1]["zt_prev"]`），**不必补抓 D2**。
- 同花顺板块指数 `bk_885xxx` 日期为 **`YYYYMMDD`**（计算前须归一化）。早期 `out/ths_concept_all.json` 的 `name` 是**双重转义字面量**，中文 `in` 全失败 → 用 `chr()` 码点或 `unicode_escape` 还原。
- **同名 key 的残留赋值会静默覆盖正确值**（`K["ZBJ_FLOW20"]` 被后面 `*0` 覆盖成 0）。改生成脚本后必须重新截图核对关键数字。
- **文本语料（评论/舆情）词频统计用 SQL `SUM(col LIKE '%X%')` 一次批量算上百个关键词**，别拉全量文本回本地分词——快、精确、可复现。简称要合并，但须剔除同名误匹配。
- 腾讯 `qt.gtimg.cn` 快照字段：**f44=流通市值、f45=总市值（单位亿元）**，f3=现价、f30=时间戳（前 8 位 YYYYMMDD）；响应 **GBK**。批量 25 只/次。`statistics` 模块**没有 `log10`**，须 `import math`。
- Mann-Whitney U / Spearman 可用标准库手算（秩次 + z 近似），不必引 scipy——`|z|>1.96 ≈ p<0.05`，适合快速显著性自检。

## 报告规范

- 浅底深字、结论先行（首屏 lead + KPI 卡）、ECharts 5、**红涨绿跌**。
- **正文数字一律由数据推导 + `__占位符__` + `.replace()` 注入，禁止手写**；收尾 `re.findall(r"__[A-Z_0-9]+__", html)` 确认无残留。**不要用 f-string 生成含 CSS/JS 的 HTML**。占位符值**自带符号**时前缀勿再补 `+`（否则 `++11.6%`）。
- ECharts 横向条形图**类目 >25** 时容器高 ≈ 类目数×21px 且 `axisLabel:{interval:0}`（**须写在对象里**，传纯数组会被抽稀）。类目轴**首项在底部** → **排名类数组传升序**（先反转再喂 `yAxis.data`）。双 Y 轴图例用 `top:3,left:'center'`（**不要 `right:8`**），`grid.top≥52`。瀑布图不能 `data:[[起,止]]`，须「透明占位 stack + 数值 stack」。
- 交付前：`_check_js.py <html>` + `_shot.py <html> <scrollY...>`（用系统 3.11）。`_check_js.py` 依赖 `node` 在 PATH，managed 环境常报 `FileNotFoundError`（**非报告问题**）→ 用绝对路径 node 手动 `--check`。
- **三列对比表「增量列」整型分支会双符号**（`"+{}".format("{:+d}")` → `++20`）：整型用 `"{:d}"`、符号交给前缀；生成后 `grep -o '++[0-9]'` 必须为空。
- **行业迁移表排序须含变化幅度权重**：只按 `-(hy0*2+hy1)` 会把「3→0 清零行业」挤出前 18 行 → 用 `-((hy0+hy1)+abs(hy0-hy1)*2)`；**标题提到的行业必须在表里真的出现**。
- **ECharts 本地托管 + CDN 兜底**：`assets/echarts.min.js` + `<script src="../assets/echarts.min.js">` + `if(typeof echarts==='undefined'){document.write(CDN)}`。**「截图自检报 canvas=0」先怀疑 CDN**（jsdelivr 在 Playwright 侧间歇 `ERR_CONNECTION_RESET`）。
- **涨停/指数报告可复用件**：① 情绪三日序列 ② 各指数成交额环比表（`tbl_sty` + `amt_yoy(nm)` 读 `zt_review_{D1}.json` 的 `indexes` 补全，`idx_cmp` 只覆盖 4 个指数）③ 炸板池「回封/未回封」拆分表 ④ 昨日涨停股溢价横向条形图 ⑤ 名称族群表 ⑥ 区域题材/产业链集群表 ⑦ 行业成分轮换率（代码集合交集）。
- 报告统一**模板与脚本分离**（`zt_report_{D0}.py` + `_report_tpl_{D0}.html`）；**复制模板后先跑一次再改文案**（`sorted(key=lambda x: ...)` 里的变量名易手误）。
- **模板里 `__HY_XX__` 是「昨日」、`__HY_XX0__` 才是「今日」**（`hy0`=今日、`hy1`=昨日，但占位符命名按旧版 `xx/xx0`）→ 写「A→B」时**方向极易写反**（10-12 实测把流入端写成 `__HY_DW0__→__HY_DW__`，渲染成 4→1）。改这类文案后必须 `grep` 渲染结果逐个核对。
- `node --check` **不支持进程替换** `<( ... )`（报 `Cannot find module 'D:\proc\...'`）→ 必须先把内联 JS 落盘再 check。

## 结论沉淀（涨停复盘方法论）

**情绪四指标分工**：`涨停+炸板`（触及涨停家数）=**参与度/意愿**；封板率与回封数=**承接力**；跌停家数与封死率=**破坏力**；成交额=**唯一裁判**。
**判定顺序固定**：先算触及数看意愿 → 再看封板率/回封看承接 → 最后看跌停封死率看破坏力。只看涨停家数必然误判。

### 量能与价格的关系（成交额环比是每日必看第一张表）
- **家数增 + 量能减 = 存量向低位扩散**，不是增量入场；**家数减 + 量能增 = 增量是配置盘、打板游资在退**（必看各指数成交额增速结构），**不能读成情绪升温**。
- **全线放量 + 全线下跌 = 抛压**：**总量与价格同向放大才算增量入场，反向就是抛压。** 口径提示：成交额环比只反映换手放大，**不区分买卖方向**。
- **增量方向相反 = 调仓而非增量**：同一笔增量资金不可能同时买权重卖成长。**看放量方向永远要同时看它的涨跌符号。**
- **「成交额环比镜像反转」是最强的次日复核工具**：某方向的放量在次日缩幅最大 → 昨日放量实为场内搬家。

### 情绪形态分类（先分类再下结论）
①**承接力退潮**（参与度平、封板率降、炸板多且 0 回封）②**收缩式锁仓**（参与度↓但封板率↑、缩量；否决条件即触及涨停下滑 → 愿冲板的钱少，只因无换手才封得住；三闭合证据：涨停股合计成交、单只中位成交、封单中位）③**分歧**（参与度平、承接力小降）④**高位分歧**（参与度↑、封板率崩 = 冲板意愿在、封不住）⑤**三项同向修复**（参与度↑+承接力↑+破坏力↓，10-09 本轮首次）⑥**广度退潮型缩圈**（参与度小降 + 承接力降 + 破坏力升，**但钱没走、全部挤进一条线**；10-12）。
> **缩圈 vs 退潮的判别**：看"退出来的钱去哪了"——若某主线连板占比同步抬升（如 30%→69%）则为**缩圈**（结构性、可延续）；若所有方向连板占比一起降则为**退潮**。

### 承接力 / 破坏力 / 质量
- **承接力看「炸板回封只数/占比 + 炸板池市值结构」，不只看炸板家数**：炸板多但仅个别回封、池内中大盘云集 =「有重量的资金在有重量的品种上被打回」；炸板骤降若是"只剩小票"则含义相反。
- **破坏力的量纲 = 跌停股合计成交 ÷ 涨停股合计成交**（09-28=3.3 / 09-30=0.17 / 10-08=1.62 / 10-09=0.22 倍）。**跌停股合计成交额（而非家数）对"破坏力"更灵敏。**
- **判「跌停池是否去板块化」**：看行业离散度 + 成交额。跌停集中且成交额远超涨停股 = 板块性杀跌；分散在多行业且合计缩量 = 结束。
- **首板组 vs 连板组的溢价对比 = 最灵敏的情绪拐点探针**，每股必算。
- **跌停潮次日的「家数回来了」≠「同一批股票回来了」**：必做「今日涨停池 ∩ 前日跌停池」代码交集，算池内均值/中位/反包只数（分方向各算）。
- **「收在涨停价」不等于被计入家数**：收盘价 = 涨停价但两源涨停池都不收录、只进东财炸板池（创业板/科创板阈值 19.8%）→ 家数取两源汇总、单列披露、计入「回封」。

### 主线归因
- **行业家数持平 ≠ 行业延续**：家数持平时**必须算代码集合交集**（轮换率）。东财行业标签在题材市里分散，最大集群常 <12%。
- **`reason_type` 关键词聚类会造伪主线** → 聚类家数大 ≠ 主线，**必须同时看「其中连板数」**，真主线看高度。**被剔除的分散簇本身就是结论：分散个股同时涨停且全是首板 = 市场没有主线。**
- **主线判定优先看 `ths_block` 概念板块榜**（比行业标签/关键词聚类更快更少歧义），同样必须给「其中连板数」。
- **判断「主线是否长高」只看一个比值：概念板块的 `continuous_plate_num / limit_up_num`**（10-09 AI应用 20 家/6 连板=30% 是"集体建仓第一天"→ 10-12 文化传媒概念 16 家/11 连板=69% 是"接力成立"）。**比涨停家数本身有用得多。**
- **「2 板梯队里有多少属于该主线」是最硬的接棒证据**（10-12：2 板 14 只中 11 只=79% 系传媒/AI）；配套的证伪信号是**同源姊妹簇同日熄火**（AI安全/信创 7→2 家）。
- **区域题材与「某字辈」= 主线真空信号**（横跨多个不相关行业、或同字辈 100% ≥2 板）。**正确读法是"没有主线的信号"，不是"新主线"**；伴生现象是同批「跨界资产注入」涨停。
- **同一方向可反复发作**：「某链杀过一次」不等于结束，要看是否换到更龙头的大市值标的。
- **长假前后的题材补涨，次日兑现概率很高**，不要写成"新主线的开始"。**跨长假的基期必须显式声明**，"昨日涨停股今日表现"不能当常规隔日溢价读。

## 自建等权指数 / 板块复盘（模板见 PCB 8 月复盘）

- 脚本链：`pcb_fetch.py` → `pcb_analyze.py`/`pcb_extra.py` → `pcb_report.py`。
- **致命坑**：`cur *= (1+avg_ret(d))` 后再 `vals[base_d]=100` 会把**基期当日涨幅重复计入**。正确：遇基期日 `vals[base_d]=100.0; continue`。**任何自建指数先断言「首日收益为 0」**。
- 最大回撤须记录**回撤当时的峰值日**（`pk_at`），不能用全局 peak 日。
- 四件套：①区间涨幅 + 区间最高/最低（附距高点）②日成交额与指数的**背离**（缩量新高是重要信号）③全板块同向日 & 单日 |涨跌|≥5% 异动计数（区分 β vs Alpha）④「前期跌幅 × 本期涨幅」散点 + 回归斜率。样本池分层并**显式声明等权口径与市值加权指数不可比**。
- **形态类分组（反包/反抽/收复）必须控制前日跌幅再看市值**：大跌日小市值本来就跌得少、反包门槛天然更低；不控制变量就会把「跌幅小」误读成「资金偏好小市值」。
- **热度与收益只在极端档成立**：极热（提及 ≥30 次）标的全部下跌，但中间档无区分度。**不要写成"热度越高越差"的线性叙事**，应写"极端热度 = 拥挤度信号"。

## 样本口径铁律（季节性 / 事件研究）

- **1991-1992 上证处于无涨跌停/T+0 极端期**，月度统计起点取 **1997-01 或 2000-01**。小样本 + 极端值必看**中位数**。
- **双基准分解（剥离跳空）**：同时给 `close(T+N)/close(T-1)`（含跳空）与 `close(T+N)/close(T+1)`（剔除首日），差额 = 首日贡献。国庆节后 5 日首日贡献 ≈85%。
- **用「环境档」替代「日历标签」**：按**当年 1-8 月累计涨幅**切分（强势 >+10%/震荡 ±10%/弱势 <-10%），10 月胜率随档位单调下降（88.9%/30.8%/28.6%）。
- **区分一手来源 vs 媒体转述**，关键数字带「来源 + 时点」；严禁把自媒体/AI 生成内容当事实。
